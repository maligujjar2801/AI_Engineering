# How to run the code

[Back to the wiki home](Home.md)

The repository has no installer and no dependency file. You need **Python 3** on your machine. Bytecode checked into two `__pycache__` folders was produced by **CPython 3.14**, so 3.11 or newer is a safe bet. Day 25 uses `sqlite3`, which ships with Python. The to-do app uses `tkinter`, which ships with most official Python installers and is sometimes a separate package on Linux.

Run commands from the folder that contains the script, unless a row below says otherwise. Paths with spaces must be quoted.

## Daily exercises

From the repository root:

```bash
cd python_journey/Day-01
python greeting.py
```

Swap the folder and the filename. Days 1–15 are almost all “run the file, type the input, read the printout”.

Scripts that **read or write a file next to themselves** must be started from their own folder:

| Folder | Why the folder matters |
| --- | --- |
| `python_journey/Day-16/` | Scripts such as `create_file.py` and `.read().py` use local names like `new.txt` |
| `python_journey/Day-19/mini project/` | `log_stream_processor.py` and `app.log` |
| `python_journey/Day-21/mini_project/` | `log_file_context_manager.py` and `log_file.log` |
| `python_journey/Day-25/` | Every script opens `database.db` in the current directory |
| `Projects/Expense Tracker/` | `Expense Tracker.py` opens `Expense.txt` |

Filenames that start with a dot or contain spaces need quotes:

```bash
cd python_journey/Day-16
python ".read().py"
python "functions in file handling.py"
```

## Day 25 — database

```bash
cd python_journey/Day-25
python CREATE.py
python INSERT.py
python READ.py
python UPDATE.py
python DELETE.py
python sqlite3_CURD.py
```

`database.db` is already committed. Running `CREATE.py` against that file may say the table already exists. Read `CREATE.py` before you run it a second time. Use `READ.py` any time you want to see the rows.

## Day 26 — package and tests

The README’s commands assume your shell is **inside** `python_journey/Day-26`, so Python can see the `study_tracker` package:

```bash
cd python_journey/Day-26
python -m study_tracker
python -m unittest discover -s tests -v
```

Do not run those two commands from the repository root. Python will not find the package.

You can still run a single example module by path:

```bash
python python_journey/Day-26/examples/import_demo.py
```

Check `import_demo.py` if that fails: it may import `temperature` as a neighbour module, which also requires the `examples/` directory to be the working directory.

```bash
cd python_journey/Day-26/examples
python import_demo.py
```

The READMEs for the discount engine, the media catalogue, the player, and the expense tracker mention `discount_strategy.py`, `media_catalogue.py`, or `main.py`. Those names are not in the tree. The commands above are the ones that match the files.

## Tkinter

`To do List.py` opens a window. It will fail on a machine with no display, and on a Linux install of Python built without Tk. The short Tkinter files inside `Projects/Expense Tracker/` are the same kind of program. Everything else in the repo is a terminal program.

## VS Code

- Root [.vscode/settings.json](https://github.com/maligujjar2801/AI_Engineering/blob/main/.vscode/settings.json) enables unittest discovery for files named `*test.py` and disables pytest. That matches Day 26’s `tests/test_study_tracker.py` only if the working directory for tests is `python_journey/Day-26` or the test is collected in a way that can import `study_tracker`. The simplest path is still the `unittest` command above.
- [Projects/.vscode/launch.json](https://github.com/maligujjar2801/AI_Engineering/blob/main/Projects/.vscode/launch.json) debugs the file you currently have open.

## Things you should not “run”

| Path | Why |
| --- | --- |
| `**/__pycache__/*.pyc` | Generated bytecode |
| `Day-25/database.db` | SQLite data, not a script |
| `*.md` | Notes. Read them. Don’t pass them to Python |
| `.github/agents/...` under Day 19 | An editor note, not a lesson script |
