## Learning workflow

Use a repeatable cycle for each study day:

1. **Learn:** read the concept and its syntax.
2. **Understand:** trace examples and predict output before running them.
3. **Practise:** make small changes and solve a short exercise independently.
4. **Build:** apply the concept in a small, meaningful program.
5. **Test:** check normal cases and edge cases; investigate unexpected behaviour.
6. **Document:** record the mental model, common mistakes, and useful examples in Markdown.
7. **Review:** revisit mistakes and explain the solution in your own words.
8. **Version:** commit coherent changes and track progress on GitHub.

## Suggested progression

- **Foundations:** syntax, data types, control flow, strings, collections, and functions.
- **Reusable code:** modules, exceptions, file handling, comprehensions, decorators, and context managers.
- **Data structures and problem solving:** dictionaries and sets, hashing, linked structures, recursion, and algorithmic thinking.
- **Software habits:** testing, readable code, documentation, Git/GitHub, and debugging.
- **Practical projects:** small command-line tools, data-processing utilities, and applications combining multiple concepts.
- **Next steps:** databases and SQL, APIs, then focused software or AI/ML learning once the foundations are solid.

**Progress principle:** Understand → practise → build → test → document → commit → review. Consistency and independent problem-solving matter more than rushing through a checklist.
